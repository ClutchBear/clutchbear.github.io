> **摘要**：在一台飞牛（fnOS）NAS 上，用自带虚拟机装一个 Linux 系统（CachyOS），从建虚拟机一路做到界面变中文、能打中文、能连上 NAS 的共享文件夹。全文按实际操作顺序写，尽量说人话，术语都给白话解释，凡是"实测通过"的结论都标了来源。

---

## 开头先说三条最重要的结论

1. **建虚拟机时，"主板固件"必须选 `UEFI`。** 选成 `Legacy BIOS` 的话，CachyOS 根本装不上，而且**建完就改不了**，只能把这台虚拟机删了重建。这是唯一一个"选错就救不回来"的选项。
2. **资源别给太少。** CPU 至少给 4 核、内存至少 8GB。只给 1 核的话，装 CachyOS 会慢到你以为它死机了（社区里有人卡在"更新软件包"那一步 20 分钟没动静）。
3. **不需要折腾命令行。** 网上有一堆"必须 SSH 进去用 `virsh` 改 CPU 模式"的教程——**在这台飞牛的虚拟机上不需要**。实测飞牛的虚拟化默认就已经把 CPU 的高级能力传给了虚拟机。文章里附了一条 30 秒就能自检的命令。

如果你只想快点把系统装上，看前六节就够了；后面的"常见问题"和"走过的弯路"可以遇到问题时再翻。

## 一、动手前，先搞懂几个词

不说清这几个词，后面全是天书。用大白话过一遍：

| 词 | 白话解释 |
|---|---|
| **虚拟机（VM）** | 在一台真电脑里"虚拟"出另一台假电脑。假电脑有自己的系统、硬盘、网卡，跑在真电脑里，互不干扰。 |
| **飞牛 / fnOS** | 一套国产的 NAS 系统（NAS = 家用小服务器，专门存文件、跑服务）。它自带一个"虚拟机"应用，就是我们这次要用的东西。 |
| **CachyOS** | 一个 Linux 系统。特点是对 CPU 做了"激进优化"，跑得比较快；它是 Arch 系（跟知名的 Arch Linux 同宗）。 |
| **指令集 / AVX2 / x86-64-v3** | 可以理解成 CPU 的"技能等级"。某些软件要求 CPU 至少有某个等级（AVX2 对应 v3 档），等级不够就装不上。 |
| **UEFI / Legacy BIOS** | 电脑开机时"找系统"的两种不同方式。新版是 UEFI，老版是 Legacy。**现代 Linux 只认 UEFI 这一种**。 |
| **分区** | 把一块硬盘切成几块区域，分别用来放"开机引导文件"和"系统本身"。 |
| **locale（区域设置）** | 决定"程序说话用哪国语言、时间用哪种格式"的设置。中文界面要靠它。 |
| **SMB / 共享文件夹** | 局域网里共享文件的方式。你 NAS 上的"共享盘"，Windows 能映射成 `Y:` 盘，Linux 也要用同样的方式连。 |

## 二、第一步：建虚拟机，这几个选项别选错

在飞牛的"虚拟机"应用里新建一台，会弹出一个配置向导。下面每一行都对照真实界面来说，并标注**哪些建完还能改、哪些改不了**。

| 配置项 | 界面里的选项 | 该怎么选 | 建完能改吗 |
|---|---|---|---|
| **主板类型** | `Q35` / `i440fx` | `Q35`（跟着默认走） | ❌ 不能改 |
| **主板固件** | `Legacy BIOS` / `UEFI` | ⭐ **`UEFI`（必须）** | ❌ 不能改 |
| **CPU 类型** | `硬件虚拟化` / `软件虚拟化` | `硬件虚拟化`（就是"用真 CPU 帮忙加速"） | — |
| **CPU 核心** | 1 核 ~ 6 核 | **4 核起**（界面上是 1 核的话，太少了） | ✅ 能改 |
| **显示类型** | `vmgga` / `vga` / `virtio-gpu` | ⭐ **`virtio-gpu`** | ✅ 能改 |
| **存储总线** | `VirtIO Block` / `VirtIO SCSI` / `SATA` / `IDE` | ⭐ **`VirtIO SCSI`** 或 **`VirtIO Block`** | ✅ 能改 |
| **网卡类型** | `VirtIO` / `Intel E1000` / `Intel E1000E` / `Realtek RTL8139` | ⭐ **`VirtIO`** | ✅ 能改 |

### 为什么固件必须选 UEFI（这条最重要）

CachyOS（以及几乎所有现代 Linux）的光盘镜像**只支持 UEFI 开机**，不认老的 Legacy BIOS。而飞牛官方文档写得很清楚：**主板类型和主板固件建完就不能改**。

所以：**如果你现在这台虚拟机的固件是 `Legacy BIOS`，只能删掉重建，选 `UEFI`。** 没有别的办法。这一条对装任何 Linux 都成立，不只是 CachyOS。

### 显示 / 存储 / 网卡为什么都选 VirtIO

网上很多教程说"选 VirtIO 得先装驱动 ISO"——**那说的是 Windows**。Linux 内核自带 VirtIO 驱动，装完直接就能认盘、认网卡、认显卡，不用挂任何驱动光盘。所以 Linux 这边没理由选老的 SATA、E1000，**VirtIO 性能更好、还零驱动**。

### 关于"指令集不够"这件事：实测结论

网上（包括本文早期版本）都说"飞牛虚拟机装 CachyOS 会因为 CPU 缺 AVX2 装不上，必须 SSH 进去改用 `virsh` 改 CPU 模式"。

**实测推翻了它。** 按 CachyOS 官方给的判读标准，在虚拟机里跑这一条命令（Live 环境里就能跑）：

```bash
/lib/ld-linux-x86-64.so.2 --help | grep supported
```

实测输出：

```
x86-64-v3 (supported, searched)
x86-64-v2 (supported, searched)
```

看到 `x86-64-v3` 后面**带着 `(supported, searched)`** 就算过关——**说明飞牛默认已经把 CPU 的高级能力透传进来了，不需要任何额外操作。**

这条命令不是第三方小工具，而是 glibc（Linux 的底层库）自己在报"我实际能用哪些指令集"，Rocky / openSUSE / CachyOS 三家官方文档都推荐用它来判定，结论可信。

> 顺带一个冷知识：Intel 从 12 代（Alder Lake）开始，因为大小核架构冲突，硬件层面禁掉了最高档的 AVX-512，所以这类 CPU 最高只能到 v3 档，到不了 v4。别拿这条命令报出的 v4 结果当真理。

**那 `virsh` 那套还有用吗？** 有用，但不是在你这台飞牛上。留着它的场景是：以后你换到别的虚拟化平台（VirtualBox / VMware / 其他 NAS），又撞上"装不上、报 CPU 架构不合法"，那时候才需要用。属于备用知识。

## 三、第二步：装系统，安装器一步步走

虚拟机建好、把 CachyOS 的 ISO 镜像挂上去、开机，就会进入安装器。它的界面是 **CachyOS Installer**（基于 Calamares 定制），底部有一条步骤条，一共 11 站：

```
Welcome → Location → Keyboard → Bootloader → Partitions → Desktop → Packages → Users → Summary → Install → Finish
```

下面按实际选择逐站说明。**没提到的站保持默认就行。**

| 步骤 | 推荐选择 | 说明 |
|---|---|---|
| **① Welcome（语言）** | `American English` | 这是**系统程序的语言**。想直接用中文界面也没问题，后面第四节教你怎么改。 |
| **② Location（位置）** | Region = `Asia`，Zone = `Shanghai` | 选上海 = 时区对。界面里还有一个"数字和日期格式"，可以单独设成 `简体中文 (中国)`——**它和系统语言是两个独立设置**，别混。 |
| **③ Keyboard（键盘）** | `Generic 105-key PC` / `English (US)` / `Default` | 标准 PC 键盘的默认值。接了机械键盘的话，用界面里那行"Type here to test your keyboard"敲两下验证下。 |
| **④ Bootloader（引导器）** | ⭐ **`GRUB`** | 界面默认高亮的其实是 **Limine**（CachyOS 2026 年 1 月起的官方默认）。但**虚拟机里建议改选 GRUB**，理由见下方小字。 |
| **⑤ Partitions（分区）** | 设备选对那块盘、模式 `Erase disk`、文件系统 `btrfs`、不勾加密 | `Erase disk` = 整盘格式化（**会清光这块盘的数据**）。btrfs 支持快照，出问题能回滚。 |
| **⑥ Desktop（桌面）** | `Plasma Desktop` | CachyOS 的旗舰桌面，官方投入最多。只当纯服务器、用命令行的话可以选 `No Desktop`，更省资源。 |
| **⑦ Packages（软件包）** | 保持默认，一个都不用改 | 默认已经勾好了四个（含 `Base-devel`，以后自己编译软件用得上）。界面上那一长串 GNOME / Xfce 之类**都是不勾的备选桌面**，别去动。 |
| **⑧ Users（用户）** | 填用户名、主机名、密码 | 别留空密码。 |
| **⑨ Summary（核对）** | **逐项过一眼再点 Install** | 这是最后确认。重点看"分区"那步选的盘和文件系统对不对。 |
| **⑩ Install（安装）** | 耐心等 | CachyOS 的包很大，装得慢是正常的。 |
| **⑪ Finish（完成）** | **先弹出 ISO 再重启** | 否则重启又回到安装界面（因为光盘镜像还挂着）。 |

### 为什么虚拟机里引导器选 GRUB，而不是默认的 Limine

三个理由，都很实在：

1. **Limine 在 UEFI 虚拟机上出过翻车事故**——x86_64 UEFI 版的 Limine 曾经必须在 4GB 内存以下加载，否则会让虚拟机直接崩溃。虽然新版早修了，但这段历史说明它在虚拟机里的内存处理比较"娇气"。
2. **Limine 的卖点在虚拟机里用不上**——它主打"启动快"和"跟系统快照菜单联动"，这些是给反复重启的物理机准备的。虚拟机关机开机本来就不慢，这些好处接近于零。
3. **出事时 GRUB 更好救**——引导坏了要抢救，GRUB 的资料和工具多得多（重建引导、救援模式、教程满地都是）；Limine 出问题少，但真出问题时能用的手段也少——而你是在 NAS 虚拟机里，远程救机成本高，稳妥更重要。

> **选 GRUB 还有个隐藏好处**：分区时 GRUB 对"引导分区"的容量要求最低（512MB 就够），而 Limine / systemd-boot 那一档动不动要 4GB。

### 分区那步，看到 `512MiB` 别慌

安装器默认会给引导分区切 `512MB`。有人一看觉得太小想改大——**不用改，够用。** 原因：引导分区里只放一个几十 KB 级的小文件（`grubx64.efi` 才 100KB 量级），系统内核并不在引导分区里，而在 btrfs 的 `/boot` 上。官方给的最低要求就是 512MB，你这个正好卡在下限，足够了。真要装多个内核、玩高级引导方案时才需要加大，现在改只会给自己添麻烦。

## 四、第三步：把系统界面变成中文

先说一个容易搞混的点：**"显示中文"和"能输入中文"是完全独立的两件事。** 这一节管"看得懂"，下一节管"打得出来"。

### 4.1 为什么系统装完是英文

因为 Arch 系（CachyOS 也属于这一系）的规矩是**语言包要你自己手动生成**，不像 Debian / Ubuntu 那样自动帮你弄好。

在 KDE 的"区域与语言"里选了中文后，如果没生成语言包，会看到一个红色报错，大意是"locale 配置了，但本系统不支持自动生成，请参考发行版手册"。**这不是 bug，是设计如此。**

### 4.2 生成中文语言包

```bash
# 1. 先看一眼有哪些中文条目（行号各版本不同，别照抄数字）
grep -nE "^#?zh_CN" /etc/locale.gen

# 2. 启用中文（把 zh_CN.UTF-8 那行的注释去掉）
sudo sed -i 's/^#zh_CN.UTF-8 UTF-8/zh_CN.UTF-8 UTF-8/' /etc/locale.gen
grep -q '^zh_CN.UTF-8 UTF-8' /etc/locale.gen || echo 'zh_CN.UTF-8 UTF-8' | sudo tee -a /etc/locale.gen

# 3. 生成
sudo locale-gen

# 4. 验证（应该出现 zh_CN.utf8）
locale -a | grep -i zh_CN
```

> **只启用 `zh_CN.UTF-8` 这一行就够了**，下面那些 `GB2312` / `GBK` / `GB18030` 是二十年前的老编码，别管它们。

### 4.3 装中文字体（不装必然显示方块）

光有语言包还不够，得有字体，否则中文全显示成"口口口"。

```bash
# 推荐：只装简体中文专版的思源字体
sudo pacman -S adobe-source-han-sans-cn-fonts adobe-source-han-serif-cn-fonts
```

**为什么推荐"简体中文专版"而不是万能的 Noto CJK？** 因为 Noto CJK 是简繁日韩一把梭，它的字体优先级里**日文排在中文字前**，某些程序会把中文字显示成**日文字形**（"门""关""复"这几个字最容易露馅）。装简体专版就没这问题。

如果已经装了 Noto CJK 又撞上日文字形，三选一：卸了它只留思源 CN；或者手动调字体优先级；或者在 KDE 字体设置里把中文直接指到思源黑体 CN。

验证字体识别：

```bash
fc-list :lang=zh | head        # 能看到中文字体就行
fc-match :lang=zh-cn           # 看默认回退用哪个字体（这才是判断有没有日文字形问题的正解）
```

如果 `fc-match` 返回的是 `Noto Sans CJK JP`（注意是 JP 不是 SC），那就是日文字形优先级问题。

### 4.4 让 KDE 界面变中文

**图形界面做法**：系统设置 → 区域和语言 → Language → 修改 → 添加"简体中文" → **把它排到第一位**（KDE 支持多语言排序，只有排第一的才真正生效）→ 应用。

也可以直接写配置文件 `~/.config/plasma-localerc`：

```ini
[Formats]
LANG=zh_CN.UTF-8

[Translations]
LANGUAGE=zh_CN
```

> ⚠️ **一个关键坑**：KDE Plasma **用自己的 `~/.config/plasma-localerc`，它会覆盖系统级的 `/etc/locale.conf`**。两处不一致时以 `plasma-localerc` 为准。所以只改系统设置可能界面还是英文——**必须同时写这个文件**。

好消息是：**Plasma 装好就已经自带中文翻译了，不用另外装语言包。**（实测翻过包内容：`plasma-workspace` 里带 76 个中文翻译文件，涵盖了系统设置的各个模块。）网上那些 `pacman -S kde-l10n-zh_cn` 之类的命令**都是过时的，现在这些包根本不存在了**。

### 4.5 注销重登（不是重启）

改完语言**必须注销重新登录**，不是锁屏、也不是重启整台机器。因为这个配置只在 Plasma 桌面**启动时读一次**，正在跑的界面不会热切换。

验证：

```bash
echo $LANG $LANGUAGE      # 期望看到 zh_CN.UTF-8 zh_CN
```

看得见的效果：文件管理器 Dolphin 的侧边栏变成"图片 / 视频 / 网络 / 最近使用"等中文。

## 五、第四步：装中文输入法（能打出中文）

**显示中文 ≠ 能打中文**，这是另一件事。装输入法（fcitx5）：

```bash
sudo pacman -S fcitx5-im fcitx5-chinese-addons fcitx5-pinyin-zhwiki
pkill fcitx5     # 装完确保没有残留进程
```

| 包 | 作用 |
|---|---|
| `fcitx5-im` | 一个"包组"，一次拉齐 fcitx5 本体 + 图形配置工具 + Qt/GTK 支持 |
| **`fcitx5-chinese-addons`** | **核心**！中文引擎（拼音、双拼、五笔）都在这里 |
| `fcitx5-pinyin-zhwiki` | 基于中文维基的拼音词库，候选词质量明显提升 |

> ⚠️ **光装 `fcitx5` 只有英文**，必须装 `fcitx5-chinese-addons` 才有中文。

### 5.1 KDE 里必须做的一步：指定"虚拟键盘"

**系统设置 → 输入和输出 → 键盘 → 虚拟键盘 → 选 `Fcitx 5`。**

这一步是**成败关键**。KDE 在 Wayland 显示协议下，输入法必须由窗口管理器（KWin）来"拉起"。不在这里指定，KWin 根本不会启动 fcitx5，后面配得再对也没用。

### 5.2 只设一个环境变量

```bash
mkdir -p ~/.config/environment.d
echo 'XMODIFIERS=@im=fcitx' > ~/.config/environment.d/im.conf
```

**这里故意只设 `XMODIFIERS` 这一个。** 原因：Wayland 下的原生程序走新的输入协议，**不需要** `GTK_IM_MODULE` / `QT_IM_MODULE` 这两个老变量，全局设了反而会干扰。`XMODIFIERS` 只用来服务那些老的 X11 程序。

> 只有当你确认自己的会话是老的 X11（`echo $XDG_SESSION_TYPE` 显示 `x11`）时，才需要再补上那两个变量。

### 5.3 加拼音 + 处理冲突

```bash
fcitx5-configtool      # 图形界面配置
```

在左侧"可用输入法"里找到 **Pinyin** 加到右边。建议顺序：`键盘-英语(US) → Pinyin`。

两个常见问题：

- **报错说"Fcitx 应由 KWin 拉起"**：说明它被系统自启动和 KWin 双重拉起了。禁用前者：
  ```bash
  sudo mv /etc/xdg/autostart/org.fcitx.Fcitx5.desktop /etc/xdg/autostart/org.fcitx.Fcitx5.desktop.disabled
  ```
- **`Ctrl+Space` 切不出输入法**：被 KDE 占用了。去"系统设置 → 键盘 → 快捷键"搜一下，把冲突的快捷键清掉或改键。

排错神器：

```bash
fcitx5-diagnose      # 输入法最有用的一键诊断工具
```

> 注意：它可能会建议你设 `GTK_IM_MODULE` / `QT_IM_MODULE`，但 **Wayland 原生程序不需要**——它报这两项"未设置"是正常的，别盲目照做。

**验证与生效**：配完**注销重登**一次，然后：

```bash
fcitx5-remote          # 返回 0/1 说明能通信
pgrep -a fcitx5        # 能看到进程
fc-list :lang=zh | head -5   # 中文字体在位
```

## 六、第五步：连上 NAS 的共享文件夹（SMB）

系统装好了、中文也有了，最后一件事：**让虚拟机能访问 NAS 上的共享盘**。

有两条路，各装各的包，别混：

| 方式 | 需要装什么 | 适合场景 |
|---|---|---|
| **图形界面**（在文件管理器里输地址） | `dolphin`（**自带 SMB 支持**） | 临时访问、点点鼠标 |
| **命令行挂载**（挂进 `/mnt/xxx`） | `cifs-utils` | 长期用、脚本引用、开机自动连 |

### 6.1 图形界面：Dolphin 的正确地址写法

```bash
sudo pacman -S --needed dolphin smbclient
```

然后在 Dolphin 里按 `Ctrl+L`，地址栏输入：

```
smb://nas@192.168.1.193/data_3.5        ← 弹一次密码框，推荐日常用
```

- `nas` 是你在 NAS 上的用户名，`192.168.1.193` 是 NAS 的 IP，`data_3.5` 是共享名（换成你自己的）。
- 想看**全部**共享，用 `smb://nas@192.168.1.193/`——**末尾的斜杠不能省**。

### 6.2 ★ 那个让人抓狂的坑："No shared folders found"

**现象**：你在 Dolphin 里只输 `smb://192.168.1.193`（不带用户名），回车后标题栏显示了 IP，但正文是灰底白字一句 **"No shared folders found"**（找不到共享文件夹）——明明 NAS 上有一堆共享。

**这不是网络不通，也不是共享名写错。** 真实原因：**地址里没写用户名，程序就先按"匿名访客"去问共享列表，而你 NAS 默认不允许匿名浏览，于是返回了空列表。**

而且 KDE 是**故意不默认匿名登录的**（这是 Samba 上游出于安全考虑的建议）。所以解决办法很简单——**在地址里带上用户名**：

```
smb://nas@192.168.1.193/data_3.5
```

一旦带上用户名，程序就会走正常登录流程、弹密码框，登录后共享就都出来了。

> 顺带打消两个常见误会：
> 1. "Dolphin 需要装 `gvfs-smb`" —— **错**。Dolphin 用的是 KDE 自家的 KIO 框架，SMB 支持由 `kio-extras` 提供，而 `dolphin` 已经强制依赖它了，装完就跟身自带。`gvfs-smb` 是给 GNOME 系文件管理器（Nautilus/Thunar）用的。
> 2. "Windows 上能看见，Linux 也一定能列出来" —— 不成立。共享的"状态"和"浏览权限"是两回事：服务端可以允许你直接访问某个共享，但不允许你匿名浏览共享列表。Windows 会自动弹框补上登录，所以你觉得"Windows 好使"；Dolphin 不写用户名时就直接裸问，于是空手而归。

### 6.3 ⚠️ 一个省事但有代价的写法

还有个写法能**免弹框**，直接进：

```
smb://nas:你的密码@192.168.1.193/data_3.5
```

**为什么能成**：程序会把地址里 `用户名:密码` 这一整段原样交给底层库，直接建立带登录的连接，自然不会弹框。

**但代价是：密码明文会留在好几个地方**——地址栏里、如果点了"添加到侧边栏"还会进 `~/.local/share/kfile/bookmarks.xml`（纯文本、不加密）。所以：

> **推荐做法**：第一次用带密码的地址打通后，**马上改回不带密码的写法**（`smb://nas@...`），弹一次框、勾"记住密码"。之后密码由 KWallet（KDE 的加密密码库）保管，地址栏和书签里都是干净的。

自查有没有把密码存进书签：

```bash
grep -o 'smb://[^"]*' ~/.local/share/kfile/bookmarks.xml 2>/dev/null
```

输出里如果看到 `:密码@` 这样的片段，说明有明文残留——删掉那条书签，改用不带密码的地址重新加。

### 6.4 命令行挂载（要长期用就走这条）

想在 `/mnt/xxx` 下当普通文件夹用、或者写脚本读文件，就用这种方式：

```bash
sudo pacman -S --needed cifs-utils
sudo mkdir -p /mnt/fnos/data
sudo mount -t cifs //192.168.1.193/data_3.5 /mnt/fnos/data \
  -o "username=nas,vers=3.0,uid=$(id -u),gid=$(id -g),file_mode=0644,dir_mode=0755,_netdev"
```

各个参数的作用：

| 参数 | 作用 | 少了会怎样 |
|---|---|---|
| `uid=` / `gid=` | 指定挂上来后文件的"本地主人" | 不写的话全是 root 的，你自己反而改不动 |
| `vers=3.0` | 用 SMB3 协议去跟 NAS 协商 | 可能协商失败 |
| `_netdev` | 告诉系统这是网络挂载 | 开机检查时可能卡住 |

### 6.5 密码里有特殊符号 → 必须用"凭据文件"

**如果密码里有 `,` `:` `@` `#` 这些符号，直接写在命令里一定会解析错。** 正确做法是单独放一个凭据文件：

```bash
cat > ~/.smbcredentials-fnos <<'EOF'
username=nas
password="你的密码"
EOF
chmod 600 ~/.smbcredentials-fnos     # ★ 必须 600，否则挂载会拒绝使用
```

然后在 `/etc/fstab` 里引用它（这样密码既不进命令行历史，也不进 fstab）：

```
//192.168.1.193/data_3.5  /mnt/fnos/data  cifs  credentials=/home/用户名/.smbcredentials-fnos,vers=3.0,uid=1000,gid=1000,_netdev,nofail,x-systemd.automount  0 0
```

**`fstab` 里这三个参数很关键**：

- **`nofail`** —— **最重要**。NAS 没开机时，虚拟机开机不会卡死在半路（否则 NAS 一关机，你的虚拟机可能就起不来了）。
- `x-systemd.automount` —— 真正用到时才挂载，开机更快。
- `_netdev` —— 声明这是网络挂载。

改完 fstab，先别急着重启，验证一下：

```bash
sudo cp /etc/fstab /etc/fstab.bak      # 改前先备份，别省
sudo systemctl daemon-reload
sudo mount -a                          # 有错会立刻报出来
findmnt /mnt/fnos                      # 确认挂上了
```

## 七、常见问题速查

| 你遇到的现象 | 真正的原因 | 怎么办 |
|---|---|---|
| **安装器起不来 / 报 CPU 架构不合法** | 虚拟机 CPU 不给 AVX2 | 先跑 `ld.so --help \| grep supported` 自检；**本机实测已通过，此坑不适用**；换平台时才用 virsh 改 host-passthrough |
| **装到"更新软件包"卡住不动** | CachyOS 包大 + 资源给小 | CPU 提到 4 核、内存 8G+；耐心等 |
| **装完重启又回到安装界面** | ISO 没卸载 | 在飞牛里把光驱里的 ISO 弹出再重启 |
| **装不上，且固件是 Legacy BIOS** | Linux 只认 UEFI，而飞牛固件建完不能改 | 只能删掉虚拟机重建，固件选 `UEFI` |
| **掉进黑底 `Shell>` 界面** | 没识别到引导文件 / 提示时没按键 | 见第三节；Win11 也会这样 |
| **磁盘/网卡认不到，提示挂驱动** | 那是 Windows 的步骤 | Linux 不用，VirtIO 驱动内核自带 |
| **界面是英文** | locale 没生成 + Plasma 语言没设 | 见第四节，注意 Plasma 用自己的配置文件 |
| **中文显示成方块** | 没装中文字体 | `pacman -S adobe-source-han-sans-cn-fonts` |
| **中文显示成日文字形** | 装了 Noto CJK，日文优先级在中之前 | 见第 4.3 节 |
| **打不出中文** | 输入法没装 / 没指定虚拟键盘 | 见第五节，重点是 KDE"虚拟键盘"那一步 |
| **Dolphin 显示"No shared folders found"** | 没写用户名，被当匿名访客拒了 | 地址写成 `smb://nas@IP/共享`（见 6.2） |
| **Dolphin 里密码能进但书签泄密** | 密码明文存进了书签文件 | 改用不带密码的地址重新加书签（见 6.3） |
| **挂上了但全是 root 属主、改不动** | 没指定 `uid`/`gid` | 挂载命令加 `uid=$(id -u),gid=$(id -g)` |
| **密码明明对却认证失败** | 密码含 `,` `:` `@`，命令行解析被截断 | 改用凭据文件（见 6.5） |
| **开机卡在紧急模式** | fstab 里 SMB 挂载失败 | 加 `nofail,x-systemd.automount` |
| **安装器在"挂载分区"阶段崩溃** | 资源不够（内存/CPU/磁盘） | 磁盘给 40G+、CPU 4 核+、内存 8G+ 后重建 |
| **鼠标卡顿 / 分辨率受限** | 缺虚机增强工具 | KVM 系装 `virt-tools` |

## 八、附：走过的弯路（省得你重踩）

### 8.1 Dolphin 里 `smb://` 报"文件夹不存在"

现象：`smbclient -L` 能列出共享、命令行 `mount -t cifs` 也正常，唯独 Dolphin 里访问 `smb://192.168.1.193/data_3.5` 报"文件或文件夹不存在"。

根因和 6.2 那个坑是同一个：**KIO 没弹登录框、按匿名连，NAS 对匿名访问就回"不存在"**。

最稳的绕法：**改用 6.4 的 cifs 挂载**，完全绕开文件管理器这一层。挂载后共享就是个普通本地文件夹，什么认证弹框的破事都没有，而且读大文件更顺（图形界面打开 SMB 上的大视频会想先整份拷到本地）。

### 8.2 虚拟机 ↔ 宿主机"剪贴板互通"：走不通，已放弃

想让 Windows 主机和这台 CachyOS 虚拟机之间共享剪贴板（复制粘贴互通）——**实测走不通**。排查过：

| 检查项 | 结果 |
|---|---|
| `spice-vdagent` 服务 | 已装、在跑 |
| SPICE 通信通道 `/dev/virtio-ports/...` | 存在 |
| `xclip` 读 X11 剪贴板 | **空的** |

根因：负责剪贴板同步的那个程序是 **X11 会话的代理**，它读的是老 X11 的剪贴板。而 KDE 用的是 Wayland 新协议，**原生程序的剪贴板根本不会进 X11 那一套**，所以同步不了。飞牛官方论坛也有用户反馈同样问题（装了增强工具、勾了"同步剪贴板"仍然无效）。

**最终方案**：改用 **SMB 共享文件夹做中转**——虽然是手动触发，但 100% 可靠、不依赖任何虚拟化通道。要复制文字就写进共享盘，另一头去读。

### 8.3 一条容易犯的命令行错误

粘命令时**千万别把中文说明一起粘进终端**：

```bash
# ✗ 错误 —— 中文会被当成额外参数
pgrep -a fcitx5 是不是在跑

# ✓ 正确
pgrep -a fcitx5
```
