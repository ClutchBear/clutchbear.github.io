> 场景：Win11 家庭版 25H2、内屏 2560×1600 @175%、外接屏 2560×1440 @175%。
> 程序：`D:\tools\ReadBOOK\ReadBook.exe`，版本 **1.5.1.0**（余民，2003 年编译，PE 带 Petite 壳）。
> 现象：窗口顶部**只有一片白色**，没有菜单栏文字，标题栏也几乎空白。
> 全部数据为本机实测（Win32 API 直读 + 像素级统计）。

## 一、结论

**根因是视觉主题（visual styles），不是 DPI、不是配色、不是配置损坏。**

给这个 exe 加上兼容性标志 `DISABLETHEMES`（界面里叫「禁用视觉主题」），菜单栏立刻恢复：

```text
~ DISABLETHEMES GDIDPISCALING DPIUNAWARE
```

三条独立证据链：

| 检查 | 结果 | 说明 |
|---|---|---|
| 菜单结构 | `GetMenu` 非空、7 项，`GetMenuBarInfo` 返回 `2431×33` 矩形 | 菜单一直在，位置分毫不差，只是**没被画出来** |
| 菜单项类型 | `fType = 0x0000`（系统绘制） | 不是自绘，所以不该出现「有结构无文字」 |
| 像素扫描 | 菜单带 1200×36 全在 251–255（纯白），一个笔画像素都没有 | 确认是空白，不是浅色文字 |

关掉主题后：

```text
文件(F)  编辑(E)  视图(V)  收藏(A)  12:16  MIDI(M)  帮助(H)
```

第五项那个时间（`12:16`）是 ReadTime 插件把当前时间做成了动态菜单标题，属于正常现象。

## 二、排查过程（按顺序，前四次全是死路）

| 序 | 假设 | 做法 | 结果 |
|---|---|---|---|
| 1 | 误判「全屏模式」 | 按 Tab 切换 | 全屏是**移除菜单句柄**（`GetMenu` = NULL）；退出全屏后菜单句柄恢复，但依然白板 → 排除 |
| 2 | DPI 缩放导致高 DPI 下非客户区绘制失败 | 兼容性设「系统(增强)」后重启 | 无效 |
| 3 | 具体是哪一档 DPI 设置 | 三档全测：无标志 / `DPIUNAWARE` / `GDIDPISCALING DPIUNAWARE` | **三档完全一致**（非白像素都是 0.24%）→ DPI 彻底排除 |
| 4 | 经典界面配色被改 | 读 `HKCU\Control Panel\Colors` | `Menu=240 240 240`、`MenuText=0 0 0`，全部正常 → 排除 |
| 5 | ini 里存了坏状态 | 移走 `ReadBook.ini` 用干净配置启动 | 无关 |
| 6 | **视觉主题** | `~ DISABLETHEMES` | **菜单栏与标题栏全部恢复** |

期间还排掉两个干扰项：

- `DWMWA_NCRENDERING_ENABLED = 0`（对照：资源管理器 = 1）——它只说明 DWM 不画这块非客户区，不说明为什么不画。
- `[Window] Left=61 Right=1466 top=19 Bottom=933` = 1405×914 逻辑像素，与实际窗口 2459×1600 正好 ×1.75 —— 这解释了「整个窗口被位图放大」，但**与菜单消失无关**（DPI 三档一致已经证伪）。

## 三、机制

ReadBook 是 1999–2003 年的 MFC 程序，**没有 comctl32 v6 清单**，本来应该跑在「经典」绘制路径上。但 Win11 仍然会给它的窗口套一层主题化的非客户区绘制，结果菜单栏那块被主题接管后**画成了空白**，标题栏文字也被压到几乎看不见（浅灰压浅灰）。

`DISABLETHEMES` shim 的作用就是强制这个进程回到经典绘制路径，菜单栏、标题栏文字、窗口按钮才恢复正常。

这也解释了为什么这个故障「只在非客户区」：客户区的工具栏和正文是程序自己用 GDI 画的，从来不受主题影响。

## 四、最终设置

### 注册表（两条都要）

```text
HKCU\Software\Microsoft\Windows NT\CurrentVersion\AppCompatFlags\Layers
  D:\tools\ReadBOOK\ReadBook.exe  =  ~ DISABLETHEMES GDIDPISCALING DPIUNAWARE
  D:/tools/ReadBOOK/ReadBook.exe  =  同上
```

⚠️ **坑：这里会同时存在两条记录**，一条用反斜杠、一条用正斜杠。图形界面写进去的和脚本写进去的路径写法不同，Windows 无法判断该用哪条，可能读到旧值导致「明明设了却没生效」。**两条都要写同一个值。**

### 为什么保留 `GDIDPISCALING DPIUNAWARE`

纯 `DISABLETHEMES` 也能出菜单，但整个窗口是位图拉伸（模糊）。加上 GDI 缩放后文字在目标 DPI 重绘，实测菜单文字边缘梯度 **435,492 vs 290,112**（强边缘 4060 vs 3073），明显更清晰。

### 代价

- 工具栏按钮、复选框变成 Win95 风格（无主题）。对这个 2003 年的阅读器来说反而更协调。
- 其余程序不受影响，`Layers` 是按 exe 路径生效的。

## 五、被排除的错误方向（写下来免得再走）

1. **不是全屏模式**。全屏会把菜单句柄整个移除（`GetMenu` = NULL）；本次故障时句柄是好的。
2. **不是 DPI**。三档兼容性设置、`1.75×` 位图放大、`UNAWARE` 自检结果，全都不能解释「结构在、画不出」。
3. **不是配色**。注册表经典色全正常，且实测那片是 `255` 纯白，连 `240` 的菜单底色都不是。
4. **不是 ini 损坏**。干净配置启动同样空白。

## 六、方法论

- **先分清「没有」和「有但没画」**：`GetMenu` / `GetMenuBarInfo` / `GetMenuItemRect` 这三个 API 能直接把「结构」和「像素」拆开。本次就是靠它们证明菜单一直存在。
- **截图必须按实时坐标**：本次前几轮用了硬编码坐标，窗口被移动过，结果截到了别的窗口（白底），一度得出「纯白无笔画」的错误结论。正确做法是每轮重新 `GetWindowRect` + `ClientToScreen`，并且**先置顶再截**。
- **同一现象多变量时必须逐档 A/B**：DPI 那三档如果只测一档，就会误以为「设了系统(增强)就好了 / 更糟了」。
- **老程序的非客户区问题，先试 `DISABLETHEMES`**，比调 DPI 便宜得多。

## 八、文件夹改名就复发：根因与一键修复

**复发原因**：`AppCompatFlags\Layers` 是**按完整路径**匹配的，不是按程序名。文件夹一改名，旧条目就指向不存在的路径，shim 全部失效。

### 这次复发的具体证据

| 路径 | 值 | 状态 |
|---|---|---|
| 旧目录 `D:\tools\<改名前的文件夹>\ReadBook.exe`（反斜杠写法） | `~ DISABLETHEMES GDIDPISCALING DPIUNAWARE` | 旧路径，已失效 |
| 旧目录 `D:/tools/<改名前的文件夹>/ReadBook.exe`（正斜杠写法） | 同上 | 旧路径，已失效 |
| 现目录 `D:\tools\ReadBOOK\ReadBook.exe` | `~ GDIDPISCALING DPIUNAWARE` | **缺 `DISABLETHEMES`** |

第三条是关键：改名后又从「属性 → 兼容性」面板勾了「代替高 DPI 缩放行为」，于是系统**只写了 DPI 那半截**——Windows 的兼容性面板不知道你还需要 `DISABLETHEMES`。菜单栏因此又变空白。

> 结论：**别用兼容性面板修这个**，它写不全。要么用下面的脚本，要么手动写完整值。

### 一键修复脚本（放在程序目录，跟着文件夹走）

| 文件 | 适用 |
|---|---|
| `修复菜单栏.bat` | **推荐**。用 `%~dp0` 取自身所在目录，文件夹改名/搬家都不用改内容 |
| `修复菜单栏.reg` | 固定路径版，只适合程序仍在 `D:\tools\ReadBOOK\` 时双击 |

bat 的三个设计要点：

1. **两条都写**（反斜杠 `D:\...` 与正斜杠 `D:/...`），避免「设了没生效」那个老坑；
2. 找不到同目录的 `ReadBook.exe` 就明确报错退出，不会往注册表里乱写；
3. 改完提示**先完全退出 ReadBook 再打开**——程序退出时会把内存里的旧设置回写注册表，边运行边改等于白改。

脚本文件**必须同时满足两个条件**，缺任一个都会炸：

| 条件 | 不满足的表现 |
|---|---|
| 编码 **GBK** | 中文提示乱码；`.reg` 的 regedit 无法解析注释 |
| 换行 **CRLF** | cmd 把整段当成一行解析，报一堆 `'yers" 不是内部或外部命令`、`'正斜杠），" 不是内部或外部命令` |

第二条是这次真正踩的坑：生成时用的是 LF（Unix 换行），cmd 只认 CRLF，于是每一行被拼接错位、引号配对全乱，回显出来的都是半截字符串。

生成命令（先写 UTF-8 临时文件，再转）：

```bash
sed 's/\r$//; s/$/\r/' 源文件.utf8 | iconv -f UTF-8 -t GBK > 目标文件
```
