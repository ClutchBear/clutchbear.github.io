> **适用版本**：WorkBuddy **5.9.3**，build `d46924219e79332f49c37ccebf27292f87001b19`
> **环境**：Windows 11，系统级安装，数据目录 `C:\Users\<用户名>\.workbuddy`
> **取证方式**：本机 `swr.json` 实时缓存、`app.asar` 渲染层代码、`workbuddy.db` 会话记录、官方文档、社区实测。文末按可信度分级。

## 一、结论先行

这个任务的「模板」是**两级结构**，只点第一级不会计数：

```
选中模板胶囊（第一级，只切换选中态，不写输入框）
        ↓
点击该模板下方 4 条 ↗ 短句之一（第二级，把完整长提示词填入输入框）
        ↓
点发送 / 回车，等首句回复出现
```

判别关键不是「短句带不带 ↗」，而是**当前有没有选中模板胶囊**：

| 状态 | 底部 4 条 ↗ 短句的身份 | 是否计数 |
|---|---|---|
| 未选中任何胶囊 | 首页默认推荐词（如「这个周末，附近有什么值得去」「每月定投1000元…」） | ❌ 无 `template_id` |
| 已选中某个胶囊 | 该模板的 `promptTitles`，对应 `prompts[n]` 完整提示词 | ✅ 带 `template_id` |

官方任务文案是「**使用 5 个模板发起对话**」，两个条件都要满足。

**实证说明**：以上时间戳取自本机 `workbuddy.db` 的 `sessions` 表，5 条会话标题与所选提示词语义一一对应。会话记录的 `source_mode` 均为 `craft`、`conversation_origin` 为 `None` —— **本地数据库不记录模板来源**，计数在服务端，因此本机只能证明「对话确实发起」，不能独立证明成长计划进度已到 5/5。

**进度数字与奖励到账以成长计划界面为准**，本机不可核验。另注意 19:11:47「查询本周末活动推荐」是无效的那一次（未选中模板的默认推荐词），不计入这 5 个。

**刻意避开的模板**：制作PPT、深度研究、开发网站、Agent应用（执行时间长、Credits 消耗高）；**定时任务**（提示词会真的去创建自动化任务，不要在只为完成成就时点）。

## 三、标准操作步骤

| 步 | 操作 | 判据 / 注意 |
|---|---|---|
| 0 | 打开左下角头像 → 成长计划，确认任务内**没有待点的「去完成」** | 多篇社区攻略把「没先点去完成」列为头号坑，未激活则做完全不记进度 |
| 1 | 回首页大输入框，点顶部「办公 / 开发 / 设计」切换场景 | 三大类只是场景切换，本身不算模板使用 |
| 2 | 点那一排胶囊中的**一个模板名**（如「创作文档」） | 只切换选中态，输入框**不会**自动填入 —— 这是正常设计，不是 bug |
| 3 | 点底部 4 条 ↗ 短句中的**一条** | 输入框应出现一大段完整提示词（不是短句本身） |
| 4 | 确认文字是实色、能点出光标删字 | 若弹「✓ 已添加到剪贴板」而输入框仍空，点输入框按 **Ctrl+V** 粘贴（客户端填入失败时的复制兜底） |
| 5 | 点输入框右下黑色圆形白上三角 ▲ 或回车发送，**等首句回复出现** | 秒关窗口可能不计入「发起对话」 |
| 6 | 回成长计划刷新，确认 **0/5 → 1/5** | **动了再继续**，别一口气发完 5 次 |
| 7 | 换 5 个**不同模板**重复，间隔几十秒至数分钟，5/5 后手动点「领取奖励」 | 奖励不自动发放；同一模板重复只计一次 |

**第 1 个原样发送、不要删改提示词**。官方文档允许「填入后根据需求修改再发送」，但改短后是否仍被判定为模板使用**未经官方确认**，也未经本机验证，拿第一个做基准最稳。

## 五、判定机制的证据链

### 5.1 实时模板表的位置

```
C:\Users\<用户名>\.workbuddy\storage\
  <用户档案目录>\
  scoped\<scope-hash>\swr.json
```

键名：`["home:remote-scenes:v1","https://download.codebuddy.cn/plugin-marketplace/scenes-v2.json"]`，其 `.data` 为 **13 个 scene**，字段含 `id` / `unified_id` / `name` / `mode` / `promptTitles` / `prompts` / `interactionModes` / `plugins`。

- `mode=working` 7 个：创作文档、金融服务、分析数据、制作PPT、深度研究、策划方案、定时任务 —— 与办公页 7 个胶囊逐字一致
- `mode=coding` 6 个：日常开发、开发网站、小程序、Agent应用、开发Skill、技术文档
- 「创作文档」完整条目：`id=47 / unified_id=130 / interactionModes=[craft,plan] / plugins=[workbuddy-docx]`，4 条 `promptTitles` 与界面底部 4 条 ↗ 短句逐字一致

> 🔴 **判据**：要查「当前界面有哪些模板」，只读 `swr.json` 的 `home:remote-scenes:v1`。
> 不要读 `home-first-screen-cache.json` 的 `templates:local:zh-cn`（那是旧缓存）。
> 日志里 `[home-fs-cache] region=templates ... count=25, bytes=23896` 是另一次拉取的字节计数，**不是模板总数**。

### 5.2 客户端代码

在 `resources\app.asar` 内可定位：

| 符号 | 作用 |
|---|---|
| `HomeComposer.onQuickActionClick` | 只做 `selectedQuickAction` / `onQuickActionSelectedChange`，不写输入框 |
| `HomePromptList` | `pageSize=4`，`onPreview` 悬停灰色预览，`onPick` 才填入完整提示词 |
| `normalizeSceneEntry` | 处理 `promptTitles` + `promptStyleTemplateIds` |
| `reportTemplateUsed` | 上报事件 **`template_used`**，参数 `{task_mode, mode, template_name, template_id, prompt_index}` |
| `agent_task_created_with_template` | 任务创建时上报 |

`template_used` 带 **`prompt_index`**，说明判定需要「选中模板 + 选到具体某条提示词」；另有任务创建事件 ⇒ 「点模板」与「发起对话」两级都做才算完整。

### 5.3 官方文档

`Create-Task` / `Task-Bar` 两页说明：模板是创建任务页按场景提供的一组提示词卡片，**悬停显示灰色预览、点击才填入输入框**，填入后可根据实际需要修改再发送。

## 六、可复现的核验命令

**列出当前客户端真实模板**（Git Bash，`python` 用内置即可，纯标准库）：

```bash
python - <<'PY'
import json, glob, os
base = os.path.expanduser("~/.workbuddy/storage")
p = glob.glob(os.path.join(base, "*", "scoped", "*", "swr.json"))[0]
d = json.load(open(p, encoding="utf-8"))
key = [k for k in d if "home:remote-scenes" in str(k)][0]
for s in d[key]["data"]:
    print(f"{s['mode']:<8} id={s['id']:<4} uid={s['unified_id']:<5} {s['name']}")
    for i, t in enumerate(s.get("promptTitles") or []):
        print(f"           [{i}] {t}")
PY
```

**判断某段提示词是不是真模板**：在 `swr.json` 的 `promptTitles` / `prompts` 里搜该文案，命中才是模板；只出现在首页默认推荐位的不算。

**核对本次会话**：

```bash
python - <<'PY'
import sqlite3, datetime, os
c = sqlite3.connect("file:" + os.path.expanduser("~/.workbuddy/workbuddy.db") + "?mode=ro", uri=True)
for t, ts in c.execute("select title,created_at from sessions order by created_at desc limit 12"):
    print(datetime.datetime.fromtimestamp(ts/1000).strftime("%m-%d %H:%M:%S"), "|", t)
PY
```

## 七、注意事项与边界

1. **Credits 成本**：5 次对话都会消耗额度。优先纯文字模板，模型用低成本档即可；不必刻意切换。
2. **别连发**：社区实测短时间连发 4 条只入账 1 条。本次 5 条间隔 4–35 分钟，无此问题。
3. **同一模板只计一次**：必须换 5 个不同模板名，换同一模板下另一条提示词不算新增。
4. **「定时任务」不要点**：其提示词会真的创建自动化任务，容易多出一条不需要的定时任务。
5. **模板列表会变**：全部由服务端下发，随时可能增删，以界面实际显示为准。不要照抄任何攻略里的模板名。
6. **进度在服务端**：本机 `sessions` 表不记录模板来源，无法离线核验 5/5；奖励需手动领取。
7. **版本关联**：本机 5.9.2 曾因「检查更新」按用户灰度返回 204 而提示已最新，5.9.3 是手动下载官方包覆盖安装。模板行为以 **5.9.3** 为准，旧版本不保证一致。

| 级别 | 内容 |

## 九、排查复盘（避免以后再绕路）

对「模板是什么」的判断更正过三次，值得记下：

| 时间 | 判断 | 问题 |
|---|---|---|
| 11-12 19:08 | 首页 ↗ 短句填入即算模板 | 未区分「默认推荐词」与「模板下的提示词」，实测 0/5 |
| 11-12 19:35 | 胶囊不是模板、带 ↗ 一律不算 | 读了**过期缓存** `home-first-screen-cache.json`（32 条），并据此给出界面上不存在的模板名 |
| 11-12 19:50 | 胶囊就是模板本体，但需再点底部短句 | ✅ 正确。数据源 `swr.json → home:remote-scenes:v1`，与界面逐字对应，并由 `app.asar` 代码与 5 条会话实证交叉验证 |

**教训**：服务端下发的 UI 数据存在多份本地缓存，旧缓存会给出看似合理但完全错误的结论。遇到「界面显示什么」这类问题，要先确认哪份缓存对应当前界面（写入时间 + 与截图逐字比对），再下判断。
